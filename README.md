## ✨ 项目简介

**Airi Core** 是一款适用于 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 的辅助插件，围绕 QQ 机器人常见的交互场景提供一组可以独立开关的功能：AI 对话唤醒（@Bot / 关键词）、LLM 主动 @ 与禁言、好友申请和群邀请审批、入群欢迎、戳一戳排行榜，以及 QQ 空间新说说自动点赞、资料卡点赞自动回赞。

无需为了这些功能单独拼接多套脚本；在 AstrBot 插件面板中即可按功能分组管理。

> [!NOTE]
> 本插件主要面向 **QQ / OneBot v11（aiocqhttp）** 环境，并兼容部分 **SnowLuma** 上报方式。不同接入端的事件和接口支持情况可能不同。QQ 空间功能依赖非官方接口，不能保证覆盖所有动态。

## 🌷 核心功能

| 模块 | 你可以做什么 |
| :--- | :--- |
| **💬 AI 对话与互动** | 支持 `@Bot`、关键词唤醒、群/私聊白名单；自动识别 QQ 官Bot；跨节点的 `@Bot 命令` 只回复命令、不额外唤醒 LLM |
| **🛡️ 群管理** | 可选 LLM 群禁言工具，自定义允许的禁言时长；禁言需要相应群管理权限 |
| **🎉 入群欢迎** | Bot 加入新群后发送自定义欢迎文字与图片；`/help` 可发送同一组欢迎内容 |
| **📮 好友申请与群邀请** | 自动同意好友申请，或将好友/群邀请交给指定 QQ 私聊审批 |
| **👆 戳一戳排行榜** | 统计群友戳 Bot 的次数，生成带头像的日榜、历史榜、全局榜及跨群榜 |
| **💗 QQ 空间自动点赞** | 定时扫描好友新说说，队列持久化、限速点赞、状态二次核验、断点续处理 |
| **💞 资料卡自动回赞** | 收到资料卡点赞通知后，当天针对同一用户执行一次尽量点满的回赞流程 |

<details>
<summary><strong>了解一些设计细节</strong></summary>

- **按需启用**：不同功能独立开关。LLM 工具仅在启用时注册，避免无意义的工具开销。
- **复用会话**：@Bot 唤醒会沿用 AstrBot 当前对话；处理引用图片失败时，不会假装识别成功。
- **只统计有效 Poke**：只有群友戳机器人本人时才计数，群友互戳不算。
- **数据跨重启保留**：Poke 统计、待审批请求、QQ 空间队列和资料卡回赞记录分别持久化。
- **保护原配置**：旧版扁平配置可自动迁移为分组配置，新功能单独成组，不需要手工删除旧配置。

</details>

## 🚀 快速开始

### 1. 环境准备

| 项目 | 说明 |
| :--- | :--- |
| AstrBot | 使用支持插件安装和配置管理的 AstrBot 4.x 环境 |
| QQ 接入 | QQ 相关能力使用 **OneBot v11 / aiocqhttp**，可搭配 SnowLuma |
| Python 依赖 | `Pillow>=10.0.0`，用于生成排行榜图片 |
| 中文字体 | 建议 Linux / ARM64 环境安装 Noto CJK，避免排行榜中文乱码 |

### 2. 安装插件

1. 打开 **AstrBot WebUI → 插件管理**。
2. 选择从 GitHub 仓库安装插件，填写仓库地址：

   `https://github.com/Lidure/astrbot_plugin_airi_core`

3. 安装完成后，进入 **Airi 核心工具🌸 → 配置**，按需启用功能。
4. 如更新后提示插件重载，按照面板提示重载插件即可；不需要修改 AstrBot 或 SnowLuma 源码。

> [!TIP]
> 第一次使用推荐先测试 `@Bot 你好` 和 `/poke排行`。QQ 空间自动点赞**默认关闭**，请确认使用需求后再单独开启。

### 3. 最简单的使用示例

```text
@Bot 你好
@Bot 帮我看看这张图片
/poke排行
/poke群排行
/空间点赞 状态
```

注意：`/空间点赞` 命令仅允许配置的 QQ 空间管理员使用。未填写管理员 QQ 时，任何人都不能通过命令控制点赞功能。

## 📖 命令速查

### 戳一戳排行榜

| 命令 | 说明 |
| :--- | :--- |
| `/poke排行` | 当前群今日个人排行 |
| `/poke总排行` | 所有群今日个人总排行 |
| `/poke历史排行` | 当前群历史个人排行 |
| `/poke历史总排行` | 所有群历史个人总排行 |
| `/poke群排行` | 各个群今日戳 Bot 次数排行 |
| `/poke历史群排行` | 各个群历史戳 Bot 次数排行 |

所有排行榜**默认展示前 10 名**，数量可选，最大值受 `poke_rank_max_limit` 限制（默认 100）。

```text
/poke排行 30
/poke排行 30 123456789       # 前 30 人，并查询指定 QQ
/poke总排行 50
/poke历史排行 20
/poke群排行 10
```

个人群榜与群排行需要在相应群聊中使用。每日统计日以**服务器本地时间 04:00** 切换，历史累计榜不会在凌晨清零。

### 好友申请与群邀请

| 命令 | 说明 |
| :--- | :--- |
| `/同意申请 A001` | 同意指定编号的好友申请或群邀请 |
| `/拒绝申请 A001` | 拒绝指定编号的好友申请或群邀请 |

将「好友申请与群邀请」分组中的人工审批打开，并填写 `request_approval_qq` 后，插件会向该 QQ 私聊发送审批通知和编号。**只有指定审批 QQ 可以执行上述命令。**

如果同时启用自动同意好友与人工审批：**好友申请优先自动通过，群邀请仍进入人工审批**。SnowLuma 在部分版本中把好友申请转换为系统私聊文本，插件也提供相应兼容处理。

### @Bot 命令只让节点回复，不额外唤醒 LLM

**默认启用**「@Bot 命令只由节点回复（不唤醒 LLM）」`at_command_suppress_llm_enabled`。

| 消息 | 是否额外调用 LLM | 理由 |
| :--- | :---: | :--- |
| `@小浅子 /help` | ❌ | 带 `/` 的命令自动免 LLM |
| `@小浅子 申请头衔`（AstrBot 已匹配） | ❌ | 已由 AstrBot 注册命令处理 |
| `@小浅子 ww帮助`（配置了外部节点规则） | ❌ | 交给 gscore 等其他 OneBot 节点 |
| `@小浅子 manohelp`（配置了外部节点规则） | ❌ | 交给 Airi 等其他节点 |
| `@小浅子 今天开心吗？` | ✅ | 正常聊天，继续 LLM |

**外部节点无斜杠命令**需要在「外部节点 @Bot 命令规则」`at_command_external_rules` 中逐条添加。例如：

```text
ww帮助
=manohelp
^ww
```

- `ww帮助`：只匹配完整的「ww帮助」或其后以空格分隔的参数。
- `=manohelp`：只匹配完全相同的命令，不匹配更多文字。
- `^ww`：匹配所有以「ww」开头的命令，包括参数紧接在后面的形式。**这也可能误把以 ww 开头的普通聊天当作命令**，请谨慎使用。
- **规则只从 `@Bot` 后紧跟的纯文本开头匹配**，不扫描引用消息、图片或整段聊天中提到的命令名称。未配置的其他节点无斜杠命令，AstrBot 无法自动识别为外部节点命令。
- 命中时调用 `event.should_call_llm(True)`，**不会调用 `stop_event()`**，所以本条消息仍交给原本的 AstrBot / gscore / Airi / 其他 OneBot 节点处理和回复。若外部节点本身未配置好或未响应，本功能不会替它生成命令回复。
- 为避免误判，关键词唤醒功能中的普通文本匹配不作为「命令」依据；真正的 `@Bot` 聊天仍正常使用当前 LLM。

### 忽略 QQ 官方机器人的 @ 与关键词唤醒

**默认启用**「忽略 QQ 官方机器人唤醒 LLM」（`ignore_official_qq_bots_enabled`）。当 QQ 官Bot 在群内 `@小浅子` 时，插件会：

- 优先读取消息中的明确机器人标识；若没有，则通过 SnowLuma 的 OneBot `get_group_member_info` 查询 `is_robot`（由 QQ 官方机器人账号段分类信息生成）。
- 只有 `is_robot: true` 才忽略：既不触发插件显式 LLM 请求，也禁止本次 AstrBot 默认 LLM 请求。普通群友，包括使用常规 QQ 号接入的第三方 Bot，不会因为昵称或关键词看起来像“机器人”就被屏蔽。
- 对群内官Bot 发出的普通关键词消息也阻止触发，以避免机器人的相互调用循环；私聊不受这项过滤影响。
- 分类结果缓存 1 小时，首次查询最多等待 3 秒；当上游不支持 `is_robot`、查询异常或超时时，**放行该消息**，避免误封正常群友。也就意味着无法保证所有官Bot都一定被识别。

这项过滤**只阻止 LLM 唤醒**，不会阻止 QQ 收到消息，也不会禁用其它插件的独立命令回复。可在 AI 对话与互动分组中关闭。

### QQ 群聊与私聊关键词唤醒 LLM

在 **AstrBot WebUI → 插件管理 → Airi 核心工具 → AI 对话与互动** 配置：

| 配置项 | 默认值 | 作用 |
| :--- | :--- | :--- |
| `keyword_wakeup_enabled` | `false` | **群聊关键词唤醒**开关，独立控制群消息 |
| `keyword_wakeup_private_enabled` | `false` | **QQ 私聊关键词唤醒**开关，独立控制私聊消息 |
| `keyword_wakeup_words` | `[]` | 多个关键词，例如 `小浅子`、`Airi`；英文不区分大小写 |
| `keyword_wakeup_mode` | `contains` | `contains` = 消息任意位置包含；`prefix` = 消息去掉开头空白后必须以关键词开头 |
| `keyword_wakeup_group_whitelist` | `[]` | **仅群聊使用**：留空所有群；填写后白名单群内的任意成员都能唤醒 |
| `keyword_wakeup_user_whitelist` | `[]` | **仅私聊使用**：留空所有私聊 QQ；填写后只有指定 QQ 能以私聊关键词唤醒。配置键名不变，原有名单会保留 |

**示例：**添加关键词 `小浅子`、`Airi`。需要群聊时打开群聊开关，需要私聊时单独打开私聊开关：

| QQ 群聊或私聊文本 | 包含模式 | 前缀模式 |
| :--- | :---: | :---: |
| `小浅子，今天开心吗？` | ✅ | ✅ |
| `今天小浅子开心吗？` | ✅ | ❌ |
| `  AIRI 帮我看看` | ✅ | ✅ |
| `/小浅子 你好` | ❌ | ❌ |

- **仅 QQ / OneBot 消息生效**。群聊与私聊两个独立开关，均默认关闭，可只启用其中一个。不会处理机器人自己发的消息。
- **权限完全分离**：群聊只检查群号白名单，不检查成员 QQ；私聊只检查私聊 QQ 白名单，不检查群号。比如群白名单有群 A、私聊白名单只有 QQ `123456789`，那么群 A 的所有成员都能用关键词唤醒，而私聊只有这个 QQ 可以通过关键词唤醒。
- **特别注意：** AstrBot 原生 QQ 私聊可能本来就会自动调用 LLM。新增私聊关键词功能只在**命中**时显式调用一次并抑制原生重复请求；**不会自动禁止未命中关键词的普通私聊回复**。如想将私聊设为“只有关键词才回复”，还需要调整 AstrBot 自身的私聊唤醒/回复策略。
- **不抢占现有指令或 @ 唤醒**：`/xxx` 命令和真正 `@Bot` 的消息交给原有逻辑；群聊已被 AstrBot 唤醒的消息也不再触发关键词。私聊的原生唤醒标记会单独处理，保证关键词命中后只发起一次 LLM 请求。
- 命中后**复用 AstrBot 当前会话、人格、图片输入与 LLM 提供商**；不额外添加 system prompt，也不把关键词偷偷替换成其他内容。
- **没有关键词时即使打开开关也不会触发。**“包含模式”可能在日常对话中频繁命中并产生模型费用，建议按需设置白名单，必要时使用“前缀模式”。
- 白名单只约束关键词唤醒功能，不会禁止用户使用其他插件命令、私聊正常回复或群聊 `@Bot`。

## 💞 QQ 资料卡自动回赞

有人给 Bot 的 **QQ 个人资料卡**点赞时，插件会优先监听 SnowLuma / OneBot 的 `notify/profile_like` 通知；如果接入端没有推送通知，还会通过 **`get_profile_like` 只读接口每约 90 秒补查**最近的点赞人，再使用 `send_like` 回赞。**与 QQ 空间说说点赞完全独立。**

> [!TIP]
> 回赞采用 **「当天第一次收到通知 → 一轮尽量点满 → 当天不再重复」** 的方式，不设人为的冷却间隔，也不需要配置点赞次数。

### 只需一个开关

进入 **AstrBot → Airi 核心工具🌸 → 配置 → 资料卡自动回赞**，开启 **「收到资料卡点赞后当天一次性回赞」** 并保存。默认关闭，不会因升级而自动启用。

| 唯一配置项 | 默认值 | 含义 |
| :--- | :---: | :--- |
| `profile_like_auto_reply_enabled` | `false` | 有人点赞 Bot 资料卡后，自动尝试给该用户点满当天可用的赞 |

### 实际运行过程

```text
收到 profile_like 通知 / 90 秒补查新增资料卡赞
                  │
                  ▼
       今天是否已处理过这位用户？
           │ 是             │ 否
           ▼                ▼
         跳过          先保存处理记录
                            │
                            ▼
               本次连续调用 send_like
                每批 10 个，最多 5 批
                            │
                  ┌─────────┴────────┐
                  ▼                  ▼
             返回成功           QQ 报上限/失败
                  │                  │
            继续下一批           立即停止
                  └─────────┬────────┘
                            ▼
                  当天不再重复触发
```

- **一次回赞流程最多尝试 50 个赞**，参考常见 OneBot 资料卡点赞插件采用的 **5 × 10** 分批方式。这里的“一次”指一次通知触发的完整流程，而不是只发一个接口请求。
- QQ 实际允许数量会受账号权限、好友关系、当天余额和平台策略影响；**最多尝试 50 不代表一定成功收到 50 个赞**。
- 若已经达到 QQ 限额，或某批接口返回错误，会立即结束本轮；当天不因新通知重试，避免刷赞或重复操作。
- 按 **机器人 QQ + 点赞人 QQ + 服务器本地日期** 去重，AstrBot 重载、重启后也不会重复回赞；即使中途崩溃也不会从头再刷。
- **双通道触发**：接收 `profile_like` 通知；当 SnowLuma 不上报此事件时，定期调用只读 `get_profile_like` 读取 **机器人自身资料卡** 的近期点赞记录。两路共享每日去重记录，不会因此多回赞。
- 首次补查仅回看最近 **15 分钟** 的点赞；以后使用持久化检查时间和 **5 分钟重叠窗口** 防止接口延迟漏检。不会对很久以前的历史点赞批量回赞。
- 补查复用 AstrBot 当前 OneBot 会话，会在收到机器人消息/事件、捕获到 OneBot 对象后开始；不需要额外填写机器人 QQ 或密钥。无法调用接口时会记录警告，并在后续周期再次检查。不会把空间动态赞、消息表情赞、Poke 当作资料卡赞。
- 状态保存在 `data/plugin_data/astrbot_plugin_airi_core/profile_like_replies.json`，沿用旧版文件，不保存点赞人昵称、聊天内容或 Cookie。

## 💗 QQ 空间点赞如何工作？

```text
好友动态流 + 分批检查好友空间
             │
             ▼
      识别新说说与发布时间
             │
             ▼
     去重 → 写入持久化队列
             │
             ▼
       按每轮限额取出任务
             │
             ▼
        先读取点赞状态
             │
       ┌─────┴─────┐
       │ 已点赞     │ 未点赞
       ▼            ▼
   标记完成     随机延迟后点赞
                    │
                    ▼
             再次核验结果
                    │
           成功移除 / 失败保留
```

**例如，短时间内出现 8 条符合条件的新说说：**

| 轮次 | 最多尝试 | 队列还剩 |
| :---: | :---: | :---: |
| 第 1 轮 | 3 条 | 5 条 |
| 第 2 轮 | 3 条 | 2 条 |
| 第 3 轮 | 2 条 | 0 条 |

*示例假设每次都成功、没有新增动态，也没有访问限制。实际扫描间隔和排空时间会受接口耗时影响。*

- **不会批量追赞启用前的历史说说**。首次扫描会尽可能结合发布时间判断；无法可靠判断时采取保守策略。
- **持久化队列**：已入队动态即使从动态流消失，重启后仍可继续处理。
- **核验成功才计成功**：QQ 接口单独返回 `code=0` 不足以证明点赞实际生效，程序会只读检查 `is_dolike`。
- **失败退避**：失败任务保留并延迟重试，自动提交最多 3 次；超过限制会暂停并保留记录供检查。
- **访问保护**：遇到登录失效或 HTTP 401/403/429 等访问限制会暂停任务，不尝试绕过验证。
- **只读模式**：可用于排查扫描；测试期间发现的动态不会因为后来关闭只读而被突然补赞。
- **旧版漏赞修复**：对部分因插件更新中断而提前标记完成的近期记录，先独立核验点赞状态，再谨慎恢复入队。

> [!IMPORTANT]
> QQ 空间依赖非官方、可能变化的 CGI 接口。好友隐私权限、动态可见范围、接口返回内容和风控都可能导致漏检或点赞失败；**插件不保证 100% 覆盖或成功点赞**。

## 📊 Poke 排行榜说明

- **统计对象**：只统计群友对机器人本人的戳一戳；群友相互戳一戳不计入。
- **个人榜单**：当前群、所有群汇总、每日榜和历史榜，榜单图片带圆形 QQ 头像。
- **跨群榜单**：以每个群戳机器人次数排名，可显示群头像。
- **昵称保护**：群榜优先显示群名片，跨群个人总榜显示 QQ 昵称；图片不展示用户完整 QQ 号。
- **图片缓存**：头像缓存默认 24 小时；加载失败时优先用旧缓存或占位头像，不阻断排行榜生成。
- **每日分界**：04:00 切日；重启和离线不会清空历史累计记录。

## 🗂️ 数据存储与隐私

插件的主要运行数据位于：

```text
AstrBot/data/plugin_data/astrbot_plugin_airi_core/
├── poke_stats.json             # Poke 日榜与历史累计数据
├── pending_requests.json       # 待审批申请和邀请
├── qzone_auto_like.json        # 空间索引、处理状态与待点赞队列
├── profile_like_replies.json   # 资料卡回赞去重、冷却与每日计数
├── avatar_cache/               # QQ 用户头像缓存
└── group_avatar_cache/         # QQ 群头像缓存
```

- QQ 空间登录 Cookie 仅在运行时通过 OneBot 读取，**不保存到插件状态文件，也不应输出到日志**。
- 空间队列保存必要的账号标识、说说 ID 和处理时间等，不保存说说正文。
- 榜单生成的临时图片由插件定期清理；Poke 统计数据不会因为正常重启而清空。
- 建议备份 `data/plugin_data/astrbot_plugin_airi_core/` 及插件配置，再执行插件迁移或重装。

## ❓ 常见问题

<details>
<summary><strong>为什么 @Bot 不回复，或者图片没有被识别？</strong></summary>

检查「AI 对话与互动」是否启用 `self_mention_wakeup_enabled`，当前接入端能否提供真实 @ 消息段，AstrBot 的 LLM Provider 是否可用。若是关键词不生效，请检查群聊开关 `keyword_wakeup_enabled` / 私聊开关 `keyword_wakeup_private_enabled`、关键词列表、`contains`/`prefix` 模式、群号与用户 QQ 白名单，并确认是 QQ 群普通文本。图片回复需要上游提供可读取的图片或引用消息；如果只有“[图片]”占位文本而没有图像内容，插件不会把它当作已完成识图。

</details>

<details>
<summary><strong>为什么 Poke 排行榜人数为 0，或图片中文显示异常？</strong></summary>

只有群成员**戳机器人自己**才计数。请确认已开启 Poke 统计、OneBot 能上报群内 Poke 事件。中文乱码可在 Debian / Ubuntu 上安装字体：

```bash
sudo apt update
sudo apt install -y fonts-noto-cjk
```

如果 AstrBot 运行在 Docker 中，还需确认容器能访问该字体。

</details>

<details>
<summary><strong>为什么 QQ 空间有新动态却没有点赞？</strong></summary>

先发送 `/空间点赞 状态`，观察是否启用、是否只读、待处理队列是否积压，以及是否有风控暂停或失败任务。随后可用 `/空间点赞 扫描` 手动检查一轮。

“首次索引”表示记录历史说说，**不等于新增说说或点赞成功**。若新动态没有进入队列，也可能是发布时间无法确认、权限限制或动态流根本没有返回该内容。接口成功代码不等于真实点赞，最终以二次状态核验为准。

</details>

<details>
<summary><strong>为什么超过每轮上限的动态没有马上被点赞？</strong></summary>

扫描与点赞是分离的：本轮发现的合格动态会先保存到持久化队列，随后才按上限逐轮处理。队列任务不需要下次仍出现在好友动态流中；但**未被 QQ 空间接口返回过的动态**仍无法自动收集。

</details>

<details>
<summary><strong>为什么好友申请没有自动通过？</strong></summary>

检查「好友申请与群邀请」中的对应开关、SnowLuma / OneBot 能否正确上报申请事件，以及机器人是否具备处理权限。某些 SnowLuma 版本以系统私聊文本转发申请，插件有兼容逻辑，但并非所有接入端格式都可保证识别。

</details>
