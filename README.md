## ✨ 项目简介

**Airi Core** 是一款适用于 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 的辅助插件，围绕 QQ 机器人常见的交互场景提供一组可以独立开关的功能：AI 对话唤醒、LLM 主动 @ 与禁言、好友申请和群邀请审批、入群欢迎、戳一戳排行榜，以及 QQ 空间新说说自动点赞、资料卡点赞自动回赞。

无需为了这些功能单独拼接多套脚本；在 AstrBot 插件面板中即可按功能分组管理。

> [!NOTE]
> 本插件主要面向 **QQ / OneBot v11（aiocqhttp）** 环境，并兼容部分 **SnowLuma** 上报方式。不同接入端的事件和接口支持情况可能不同。QQ 空间功能依赖非官方接口，不能保证覆盖所有动态。

## 🌷 核心功能

| 模块 | 你可以做什么 |
| :--- | :--- |
| **💬 AI 对话与互动** | 通过 `@Bot` 唤醒 LLM；支持直接图片和引用图片；模型可按需主动 @ 指定群友 |
| **🛡️ 群管理** | 可选 LLM 群禁言工具，自定义允许的禁言时长；禁言需要相应群管理权限 |
| **🎉 入群欢迎** | Bot 加入新群后发送自定义欢迎文字与图片；`/help` 可发送同一组欢迎内容 |
| **📮 好友申请与群邀请** | 自动同意好友申请，或将好友/群邀请交给指定 QQ 私聊审批 |
| **👆 戳一戳排行榜** | 统计群友戳 Bot 的次数，生成带头像的日榜、历史榜、全局榜及跨群榜 |
| **💗 QQ 空间自动点赞** | 定时扫描好友新说说，队列持久化、限速点赞、状态二次核验、断点续处理 |
| **💞 资料卡自动回赞** | 收到他人点赞机器人 QQ 资料卡的通知后，按限额回赞（与空间说说点赞独立） |

<details>
<summary><strong>了解一些设计细节</strong></summary>

- **按需启用**：不同功能独立开关。LLM 工具仅在启用时注册，避免无意义的工具开销。
- **复用会话**：@Bot 唤醒会沿用 AstrBot 当前对话；处理引用图片失败时，不会假装识别成功。
- **只统计有效 Poke**：只有群友戳机器人本人时才计数，群友互戳不算。
- **数据跨重启保留**：Poke 统计、待审批请求、QQ 空间队列和资料卡回赞记录分别持久化。
- **保护原配置**：旧版扁平配置可自动迁移为分组配置，新功能单独成组，不需要手工删除旧配置。

</details>

## 🚀 快速开始

### 1. 环境准备

| 项目 | 说明 |
| :--- | :--- |
| AstrBot | 使用支持插件安装和配置管理的 AstrBot 4.x 环境 |
| QQ 接入 | QQ 相关能力使用 **OneBot v11 / aiocqhttp**，可搭配 SnowLuma |
| Python 依赖 | `Pillow>=10.0.0`，用于生成排行榜图片 |
| 中文字体 | 建议 Linux / ARM64 环境安装 Noto CJK，避免排行榜中文乱码 |

### 2. 安装插件

1. 打开 **AstrBot WebUI → 插件管理**。
2. 选择从 GitHub 仓库安装插件，填写仓库地址：

   `https://github.com/Lidure/astrbot_plugin_airi_core`

3. 安装完成后，进入 **Airi 核心工具🌸 → 配置**，按需启用功能。
4. 如更新后提示插件重载，按照面板提示重载插件即可；不需要修改 AstrBot 或 SnowLuma 源码。

> [!TIP]
> 第一次使用推荐先测试 `@Bot 你好` 和 `/poke排行`。QQ 空间自动点赞**默认关闭**，请确认使用需求后再单独开启。

### 3. 最简单的使用示例

```text
@Bot 你好
@Bot 帮我看看这张图片
/poke排行
/poke群排行
/空间点赞 状态
```

注意：`/空间点赞` 命令仅允许配置的 QQ 空间管理员使用。未填写管理员 QQ 时，任何人都不能通过命令控制点赞功能。

## 📖 命令速查

### 戳一戳排行榜

| 命令 | 说明 |
| :--- | :--- |
| `/poke排行` | 当前群今日个人排行 |
| `/poke总排行` | 所有群今日个人总排行 |
| `/poke历史排行` | 当前群历史个人排行 |
| `/poke历史总排行` | 所有群历史个人总排行 |
| `/poke群排行` | 各个群今日戳 Bot 次数排行 |
| `/poke历史群排行` | 各个群历史戳 Bot 次数排行 |

所有排行榜**默认展示前 10 名**，数量可选，最大值受 `poke_rank_max_limit` 限制（默认 100）。

```text
/poke排行 30
/poke排行 30 123456789       # 前 30 人，并查询指定 QQ
/poke总排行 50
/poke历史排行 20
/poke群排行 10
```

个人群榜与群排行需要在相应群聊中使用。每日统计日以**服务器本地时间 04:00** 切换，历史累计榜不会在凌晨清零。

### 好友申请与群邀请

| 命令 | 说明 |
| :--- | :--- |
| `/同意申请 A001` | 同意指定编号的好友申请或群邀请 |
| `/拒绝申请 A001` | 拒绝指定编号的好友申请或群邀请 |

将「好友申请与群邀请」分组中的人工审批打开，并填写 `request_approval_qq` 后，插件会向该 QQ 私聊发送审批通知和编号。**只有指定审批 QQ 可以执行上述命令。**

如果同时启用自动同意好友与人工审批：**好友申请优先自动通过，群邀请仍进入人工审批**。SnowLuma 在部分版本中把好友申请转换为系统私聊文本，插件也提供相应兼容处理。

### QQ 空间自动点赞

| 管理命令 | 说明 |
| :--- | :--- |
| `/空间点赞 状态` | 查看运行状态、已索引数量、剩余待点赞任务和暂停重试任务 |
| `/空间点赞 扫描` | 立即扫描一轮，并尝试处理一批队列任务 |
| `/空间点赞 开启` | 在当前运行期间开启任务 |
| `/空间点赞 关闭` | 在当前运行期间停止任务 |

启用或关闭命令只改变**当前运行状态**；插件重载或 AstrBot 重启后，仍以 WebUI 中保存的配置为准。

## ⚙️ 配置说明

插件配置已整理为 **七个功能分组**，常用开关直接显示，细节选项放在对应位置，避免在一张配置页中堆满参数。

| 分组 | 主要选项 | 初始状态 |
| :--- | :--- | :--- |
| 💬 AI 对话与互动 | @Bot 唤醒；主动 @ 工具 | 开启 |
| 🛡️ 群管理与禁言 | LLM 禁言工具；最短/最长禁言时间 | 禁言关闭 |
| 🎉 入群欢迎 | 欢迎开关；文字；图片 | 关闭 |
| 📮 好友申请与群邀请 | 自动同意好友；人工审批；审批 QQ | 关闭 |
| 👆 戳一戳与排行榜 | Poke 统计；单次排行上限 | 统计开启 |
| 💞 资料卡自动回赞 | 自动回赞开关；回赞次数；每日上限；冷却间隔 | 关闭 |
| 💗 QQ 空间自动点赞 | 自动点赞开关；扫描间隔；每轮数量；高级设置 | 关闭 |

旧版本升级时会尝试自动迁移自定义配置。**请不要为了“重新初始化”而随意删除配置文件或插件数据目录**，否则可能丢失累计榜和待处理记录。

<details>
<summary><strong>展开：QQ 空间高级配置参考</strong></summary>

| 配置字段 | 默认值 | 作用 |
| :--- | :--- | :--- |
| `qzone_auto_like_enabled` | `false` | 自动点赞总开关；开启后为实际点赞 |
| `qzone_poll_interval_sec` | `300` | 两轮扫描之间的等待时间（最低 120 秒） |
| `qzone_max_likes_per_cycle` | `3` | 每轮最多尝试点赞数；其余留在队列 |
| `qzone_dry_run` | `false` | 只读测试，读取并记录动态但不点赞 |
| `qzone_owner_qq` | 空 | 唯一允许执行空间点赞管理命令的 QQ |
| `qzone_friend_batch_size` | `8` | 每轮额外轮询的好友空间数量 |
| `qzone_feed_count` | `30` | 每个动态来源单次读取数量 |
| `qzone_delay_min_sec` | `15` | 点赞前随机延迟的最小秒数 |
| `qzone_delay_max_sec` | `30` | 点赞前随机延迟的最大秒数 |

机器人自身 QQ 会通过 OneBot 事件自动识别，无需单独填写。**同一个 AstrBot 连接多个 QQ 账号时，当前实现优先绑定最先产生有效事件的账号**，暂未提供多账号选择器。

</details>

## 💞 QQ 资料卡自动回赞

这是与**QQ 空间说说自动点赞**完全不同的功能。有人给 Bot 的**QQ 个人资料卡片**点赞时，SnowLuma / OneBot 会发送 `notice/notify/profile_like` 通知。Airi Core 根据通知中的点赞人 `operator_id`，调用 `send_like` 给对方资料卡回赞。

> [!NOTE]
> **默认关闭**，不会主动扫描陌生人的资料卡，也不会给说说、消息表情或群戳一戳自动回赞。功能依赖上游正确上报 `profile_like` 通知；如果 SnowLuma 版本没有提供该通知，插件不会自动收到点赞事件。

### 开启方式

进入 **AstrBot → Airi 核心工具🌸 → 配置 → 资料卡自动回赞**，开启“收到资料卡点赞后自动回赞”，再保存设置并按面板提示重载插件。

| 配置项 | 默认值 | 说明 |
| :--- | :---: | :--- |
| `profile_like_auto_reply_enabled` | `false` | 是否启用自动回赞 |
| `profile_like_reply_times` | `1` | 每条符合条件的通知回赞次数，范围 1–10 |
| `profile_like_daily_limit` | `10` | 每位点赞人每日最多自动回赞次数，最高 10 |
| `profile_like_cooldown_sec` | `120` | 同一人两次回赞之间的冷却时间（秒），最低 30 |

### 处理流程与安全措施

```text
对方点赞 Bot 的 QQ 资料卡
            ↓
SnowLuma 上报 profile_like 通知
            ↓
检查点赞人、Bot 身份和通知时间
            ↓
去重 / 冷却 / 每日回赞次数限制
            ↓
先保存本次尝试，防止重启重复点赞
            ↓
通过 OneBot send_like 给对方资料卡回赞
```

- **默认每条有效通知回 1 个赞**；`times` 表示对方在通知中的点赞次数，插件不会默认无上限地镜像。
- 同一人短时间内重复点赞或上游重复上报时，冷却与事件去重会避免连续发送；每日限额按服务器本地日期计算。
- 对机器人自身、格式不完整或过期的通知不回赞；`send_like` 失败会留下记录，不因未知网络状态盲目重试。
- 处理状态保存在 `data/plugin_data/astrbot_plugin_airi_core/profile_like_replies.json`，支持重启防重，不保存点赞人昵称或聊天内容。
- 需要 QQ / OneBot 接入端支持 `send_like`；对非好友或受限账号，QQ 端可能拒绝操作。插件不会绕过限制。

## 💗 QQ 空间点赞如何工作？

```text
好友动态流 + 分批检查好友空间
             │
             ▼
      识别新说说与发布时间
             │
             ▼
     去重 → 写入持久化队列
             │
             ▼
       按每轮限额取出任务
             │
             ▼
        先读取点赞状态
             │
       ┌─────┴─────┐
       │ 已点赞     │ 未点赞
       ▼            ▼
   标记完成     随机延迟后点赞
                    │
                    ▼
             再次核验结果
                    │
           成功移除 / 失败保留
```

**例如，短时间内出现 8 条符合条件的新说说：**

| 轮次 | 最多尝试 | 队列还剩 |
| :---: | :---: | :---: |
| 第 1 轮 | 3 条 | 5 条 |
| 第 2 轮 | 3 条 | 2 条 |
| 第 3 轮 | 2 条 | 0 条 |

*示例假设每次都成功、没有新增动态，也没有访问限制。实际扫描间隔和排空时间会受接口耗时影响。*

- **不会批量追赞启用前的历史说说**。首次扫描会尽可能结合发布时间判断；无法可靠判断时采取保守策略。
- **持久化队列**：已入队动态即使从动态流消失，重启后仍可继续处理。
- **核验成功才计成功**：QQ 接口单独返回 `code=0` 不足以证明点赞实际生效，程序会只读检查 `is_dolike`。
- **失败退避**：失败任务保留并延迟重试，自动提交最多 3 次；超过限制会暂停并保留记录供检查。
- **访问保护**：遇到登录失效或 HTTP 401/403/429 等访问限制会暂停任务，不尝试绕过验证。
- **只读模式**：可用于排查扫描；测试期间发现的动态不会因为后来关闭只读而被突然补赞。
- **旧版漏赞修复**：对部分因插件更新中断而提前标记完成的近期记录，先独立核验点赞状态，再谨慎恢复入队。

> [!IMPORTANT]
> QQ 空间依赖非官方、可能变化的 CGI 接口。好友隐私权限、动态可见范围、接口返回内容和风控都可能导致漏检或点赞失败；**插件不保证 100% 覆盖或成功点赞**。

## 📊 Poke 排行榜说明

- **统计对象**：只统计群友对机器人本人的戳一戳；群友相互戳一戳不计入。
- **个人榜单**：当前群、所有群汇总、每日榜和历史榜，榜单图片带圆形 QQ 头像。
- **跨群榜单**：以每个群戳机器人次数排名，可显示群头像。
- **昵称保护**：群榜优先显示群名片，跨群个人总榜显示 QQ 昵称；图片不展示用户完整 QQ 号。
- **图片缓存**：头像缓存默认 24 小时；加载失败时优先用旧缓存或占位头像，不阻断排行榜生成。
- **每日分界**：04:00 切日；重启和离线不会清空历史累计记录。

## 🗂️ 数据存储与隐私

插件的主要运行数据位于：

```text
AstrBot/data/plugin_data/astrbot_plugin_airi_core/
├── poke_stats.json             # Poke 日榜与历史累计数据
├── pending_requests.json       # 待审批申请和邀请
├── qzone_auto_like.json        # 空间索引、处理状态与待点赞队列
├── profile_like_replies.json   # 资料卡回赞去重、冷却与每日计数
├── avatar_cache/               # QQ 用户头像缓存
└── group_avatar_cache/         # QQ 群头像缓存
```

- QQ 空间登录 Cookie 仅在运行时通过 OneBot 读取，**不保存到插件状态文件，也不应输出到日志**。
- 空间队列保存必要的账号标识、说说 ID 和处理时间等，不保存说说正文。
- 榜单生成的临时图片由插件定期清理；Poke 统计数据不会因为正常重启而清空。
- 建议备份 `data/plugin_data/astrbot_plugin_airi_core/` 及插件配置，再执行插件迁移或重装。

## ❓ 常见问题

<details>
<summary><strong>为什么 @Bot 不回复，或者图片没有被识别？</strong></summary>

检查「AI 对话与互动」是否启用 `self_mention_wakeup_enabled`，当前接入端能否提供真实 @ 消息段，AstrBot 的 LLM Provider 是否可用。图片回复需要上游提供可读取的图片或引用消息；如果只有“[图片]”占位文本而没有图像内容，插件不会把它当作已完成识图。

</details>

<details>
<summary><strong>为什么 Poke 排行榜人数为 0，或图片中文显示异常？</strong></summary>

只有群成员**戳机器人自己**才计数。请确认已开启 Poke 统计、OneBot 能上报群内 Poke 事件。中文乱码可在 Debian / Ubuntu 上安装字体：

```bash
sudo apt update
sudo apt install -y fonts-noto-cjk
```

如果 AstrBot 运行在 Docker 中，还需确认容器能访问该字体。

</details>

<details>
<summary><strong>为什么 QQ 空间有新动态却没有点赞？</strong></summary>

先发送 `/空间点赞 状态`，观察是否启用、是否只读、待处理队列是否积压，以及是否有风控暂停或失败任务。随后可用 `/空间点赞 扫描` 手动检查一轮。

“首次索引”表示记录历史说说，**不等于新增说说或点赞成功**。若新动态没有进入队列，也可能是发布时间无法确认、权限限制或动态流根本没有返回该内容。接口成功代码不等于真实点赞，最终以二次状态核验为准。

</details>

<details>
<summary><strong>为什么超过每轮上限的动态没有马上被点赞？</strong></summary>

扫描与点赞是分离的：本轮发现的合格动态会先保存到持久化队列，随后才按上限逐轮处理。队列任务不需要下次仍出现在好友动态流中；但**未被 QQ 空间接口返回过的动态**仍无法自动收集。

</details>

<details>
<summary><strong>为什么好友申请没有自动通过？</strong></summary>

检查「好友申请与群邀请」中的对应开关、SnowLuma / OneBot 能否正确上报申请事件，以及机器人是否具备处理权限。某些 SnowLuma 版本以系统私聊文本转发申请，插件有兼容逻辑，但并非所有接入端格式都可保证识别。
